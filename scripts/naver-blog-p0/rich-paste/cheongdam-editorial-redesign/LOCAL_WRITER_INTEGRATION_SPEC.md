## 고정 입력·검증 계약
1. 기존 로컬 `ARTICLE_FOR_NAVER.md`, `REVIEW_CHECKLIST.md`, 필요 시 `PUBLIC_PREVIEW.html`과 `SPOKEDU_AUTOPILOT` 원본 인덱스를 먼저 탐색한다. 기존 원고가 없을 경우 자동으로 다른 사람이 새 원고를 지어내지 않는다. 작성 주체/경로를 분명히 기록한다.
2. 생성 주력은 운영자의 기존 Gemma 4 26B QAT(LM Studio). 다만 아직 실제 검수 없이 자동 발행 가능한 모델이라고 주장하지 않는다. 기존 출력은 사람이 검토해야 한다.
3. 글을 쓰기 전에 연결된 1차 수업일지의 기관/날짜/연령/인원/종목/교구/반응/성과와 원고를 대조한다. 다른 수업 사례 결합은 출처 범위를 드러내며 실제로 없었던 활동과 가짜 숫자·인용은 추가하지 않는다.
4. 검색에 자연스러운 제목, 현장 맥락, 구체적인 활동 흐름, 관찰/한계, 독자에게 필요한 배경 설명, 마무리, 상담 CTA, 관련 내부 링크(확인된 경우), 해시태그를 사용자 레퍼런스에 맞게 완성한다. 모든 글의 끝에 무조건 동일 문구를 기계적으로 붙이지 않는다. 단 CTA 존재와 URL 정확성은 자동 검증한다.
5. 본문과 연결될 수업 원본 사진을 우선 탐색한다. 이미지 사용과 아동 초상권 공개 승인 등은 별도 확인. 사진 자산의 해시와 출처를 매니페스트에 고정한다.
6. 기존 실환경 성공한 photo-first Rich Paste 실행기를 재사용한다. 단 `blockCount/headingIndexes/photoAfter`는 원고·사진에 따라 생성하고 하드코딩된 14문단/PAPS 전용 값을 다음 글에 재사용하지 않는다.
7. 네이버에서 실제 글꼴 크기·굵기·전체 블록 순서·사진 개수·제목·마무리 CTA·링크 동작을 확인해야 편집 완료다. `textMatch=true`만으로는 완료 불가.
8. 자동화는 사용자가 명시적으로 허용하기 전까지 임시저장·발행을 하지 않는다. 원본/기존 탭과 사용자의 로컬 파일은 그대로 둔다.

## 상태 정의
- `LOCAL_SOURCE_DISCOVERED`: 실제 로컬 파일·SHA 확인
- `SOURCE_REVIEW_REQUIRED`: 일지/원고 사실 검토 필요
- `CONTENT_READY`: 사실·구성·마무리·사진 매칭 승인
- `NAVER_EDITOR_PREVIEW_PASS`: 실제 네이버 입력·서식 검수 통과
- `PUBLISH_APPROVAL_REQUIRED`: 발행 금지 상태 유지

이 문서는 다음 기사 작업을 위한 구현 계약이다. **여기에 명시된 로컬 탐색·자율 기사 선정·사진 매칭이 이번 ZIP에서 모두 구현됐다는 의미가 아니다.** 이번 ZIP이 수행하는 작업은 검증된 청담 수업 자료로 만든 완성형 ChatGPT 보완 원고를 기존 편집기에 입력하는 것뿐이다.
