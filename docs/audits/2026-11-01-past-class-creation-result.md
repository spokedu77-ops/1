# 과거 수업 개설 후 종료·미처리 보완

## 원인

사용자가 새로 개설한 대치 게이트 운동회는 `5a2c6b91-b6e8-4517-84d2-ee4aab0ebffb`, 2026-10-25 14:00–18:00 KST였다. 과거 수업도 개설 화면에서 status를 opened로 고정 저장하고, 화면 진입·표시 전환·5분 간격의 자동 완료를 기다리는 구조였다. UTC/KST 비교 오류가 아니다. 상단 완료 집계는 실제 상태 대신 경과 시간만 보아 완료 1과 종료·미처리가 동시에 나타났다. 자동 완료 이벤트를 상세 패널이 구독하지 않아 갱신 후에도 이전 상태가 남을 수 있었다.

## 조치

- 개설 시 종료 시각이 현재 이하이면 처음부터 finished, 아직 종료되지 않았으면 opened로 저장한다. 기존 자동 완료의 종료 시각 기준을 동일하게 적용하며 verified 승인이나 송금은 수행하지 않는다.
- 상단 완료 수는 실제 완료 상태만 집계한다. 열린 과거 수업은 종료·미처리 건수로 구분하고 진행·예정에도 포함하지 않는다.
- 열린 상세 패널이 자동 완료 이벤트를 수신하면 진행 중 이전 조회를 무효화하고 다시 읽는다.
- 재개설한 해당 1건은 ID·제목·시각·opened 조건을 확인하고 finished로 전환했다. 변경 전후 감사 ID `ce573b66-32ac-4832-97a7-0156b7f8be80`. 운영 DB 재조회에서 finished, 주강사료 80,000원·보조 2명 각 80,000원 유지, 회차 로그 3건 확인. 이 수업의 신규 개설 수업료는 240,000원이며 앞선 3,660,000원 보고서는 재개설 이전 스냅샷이다.

## 검증 및 적용 범위

- 과거·종료 경계·진행 중·미래·UTC/KST 시각을 포함한 개설 상태/표시/자동 완료 대상 테스트 13개 통과. 변경 파일 lint, TypeScript 검사 통과.
- 로컬 1440/390/375px 격리 UI에서 종료·미처리 1건일 때 상단 완료 0, 완료 이벤트 후 재조회하여 완료 1·미처리 안내 제거를 확인했다. 기존 보조 저장 성공/실패 검증도 통과했다. UI 검증은 운영 쓰기를 차단했다.
- 코드 수정은 로컬에만 반영했다. 운영 앱 배포 및 Git stage/commit/push 없음. 운영 DB는 위에 명시한 수업 1건의 상태만 바꿨다.
