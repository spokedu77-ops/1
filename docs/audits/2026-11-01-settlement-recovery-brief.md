# 강사 정산 누락 복구 승인 범위

승인 근거: 2026-11-01 대화에서 제안한 다섯 단계 개선·재대조에 대한 사용자의 “시작”.

- 대상: 운영 강사 정산, 수업 자동 완료, 보조 배정 입력 검증. SPOKEDU MASTER 구독 제품·정산 시트는 대상이 아니다.
- 구현: 자동 완료의 개별 트랜잭션·실제 변경 건수·오류 반환, 정산 기간 내 미완료/잘못된 배정 표시, 과거 지급 대상과 현재 계정 활성 여부 분리, 명세와 총액 대조, 잘못된 보조 저장 차단.
- 보존: 운영진 지급 제외, 기존 주·보조 단가, 기타 정산, 인증·권한, 완료 시 DB 회차/마일리지 트리거. 추측으로 완료·배정·단가를 변경하지 않는다.
- 운영 복구: 사용자가 진행 사실을 제보한 10/31 가재울 건만 기존 배정·금액·시각이 동일한지 조건부 검증 후 opened → finished. 나머지 진행 미확인 건과 대치 운동회 빈 슬롯은 보류한다.
- 후속 지시 반영: 사용자가 “누락분 다 확인하라니까? 그리고 종료했는데 왜 opened”라고 재지시했다. 기존 자동 완료 코드는 피드백 제출이나 별도 출석 증빙 없이 종료 시각이 지난 opened를 finished로 전환하는 규칙이다. 이 기준에 해당하는 10월 후기 정상 배정 수업은 전부 조건부 복구한다. 위 가재울만 복구한다는 제한은 에이전트가 추가한 과도한 보류였으며 후속 지시에 따라 해제한다. verified 승인·실제 송금·새로운 단가나 강사 배정은 추정하지 않는다.
- 검증: 승인된 개선안의 검증을 구체화하여 자동 완료 라우트와 정산 계산/배정 검증의 대상 회귀 테스트, 변경 파일 lint, TypeScript 진단, 로컬 읽기 전용 화면 확인을 수행한다. 화면 점검 중 자동 완료 POST는 차단하여 운영 데이터가 추가 변경되지 않게 한다. 전체 빌드·전체 테스트는 실행하지 않는다.
- 완료 기준: 실패 한 건의 전파 차단, 실패를 성공으로 응답하지 않음, 비활성 강사 과거 지급액 표시, 명세·총액 일치, 가재울 60,000원 및 회차 로그 재대조. 실제 지급 완료는 주장하지 않는다.
- Git: stage/commit/push/deploy하지 않는다.
- 6단계 추가 승인: 사용자의 “전부 다 순서대로 해”에 따라 모든 수업 저장 경로, 보조 잔존 데이터, 상태 변경, 10월 후기 정산 양방향 대조, 실패·동시 수정·재조회, 리팩토링 전후 변경분을 순서대로 검사한다. 발견한 동일 범위 결함을 수정하고 대상 계약/단위/롤백 DB/로컬 격리 UI 검사 및 변경 파일 lint·TypeScript를 수행한다. 신규 정책·단가·배정·송금·서버 cron은 추정하거나 추가하지 않는다.
- 서버 주기 작업: 운영 cron 등록은 자동 승인 검토에서 거부됐으며 적용·우회 실행하지 않았다. 이후 미승인 초안을 제거했다. 기존 화면 접속 시 자동 완료 동작은 유지한다.
- 최신 명시 승인: 사용자가 “어 승인하고”라고 보조 삭제 검증 DB 함수 수정안의 운영 적용을 승인했다. `classops_allow_safe_assistant_removal`만 적용한다. 또한 오류가 나는 대치 게이트 수업을 DB에서 삭제하고 직접 새로 개설하겠다고 명시했다. 해당 제목·일시·ID·배정을 확인한 1건만 감사 기록 후 삭제한다. cron 등록 승인은 포함하지 않는다.
