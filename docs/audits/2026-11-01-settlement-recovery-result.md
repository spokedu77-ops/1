## 최신 상태 — 전수 복구 후

### 자동 완료 콘솔 오류 후속 수정

대치 운동회의 빈 보조 ID를 DB 갱신 전에 검증하도록 수정했다. 이와 같은 데이터 검토 결과는 HTTP 207 및 ok:false/status:needs-review로 반환하고, 실제 인프라 장애는 500으로 구분한다. 브라우저 console.error 대신 수업명·수정 이유를 담은 지속 안내와 경고를 표시하여 Next.js 오류 오버레이를 유발하지 않는다. 정상 수업 처리는 유지한다. 해당 API 회귀 테스트 7개 통과, 로컬 1440px·390px 실제 컴포넌트에서 확인 필요 안내·캘린더 사용 가능·콘솔 오류 0건 검증. 운영 데이터 추가 변경 없음.

사용자의 후속 지시에 따라 피드백을 지급 조건으로 오인한 보류를 해제했다. 기존 자동 완료 규칙은 종료 시각이 지난 opened를 finished로 전환하며 별도 피드백 제출 조건이 없다.

- 추가 정상 수업 16건(유급 10건 435,000원 + 운영진 0원 6건)을 기존 배정·금액·시각·updated_at 비교 후 운영 DB에서 복구했다. 각 변경 전후 감사 기록 16개가 있으며 배정·금액·종료 시각 변경은 0건이다.
- 앞서 복구한 가재울을 합하면 시간 종료 후 집계에서 빠졌던 유급 수업료는 11건 495,000원이다.
- 125개 최종 상태: finished 50, verified 60, postponed 12, cancelled 2, 잘못된 보조 데이터가 있는 opened 1. 완료된 모든 주·보조 배정 대비 회차 로그 불일치 0건.
- 종료된 opened에 남아 있는 **실명 배정 지급액은 0원**. 완료 수업료 합계 3,680,000원 + 기존 기타 정산 30,000원 = **3,710,000원**.
- 이승범 비활성 명단 누락은 완료 10/21 25,000원과 이번 복구 10/28 25,000원, 합계 50,000원이다. 로컬 수정 명세는 포함하며 운영 UI 배포는 아직 하지 않았다.
- 한국 시간 오류가 이번 opened 잔류 원인은 아니다. end_at은 timestamptz이며 DB now()와 절대 시각으로 비교한다. 청음복지관 10/31 종료 07:30 UTC = 16:30 KST이고 DB에서도 end_at < now() = true였다. 일괄 UPDATE의 트리거 실패와 화면 접속 의존이 원인이다.
- 화면은 시간만 지나면 완료로 표시해 저장 상태와 달랐다. 월 캘린더·날짜 패널·수업 상세에서 저장된 완료와 시간 종료를 구분하도록 로컬 표시를 수정했다(opened 종료: 종료·미처리).
- 남은 대치 게이트 운동회는 보조 ID 두 개가 빈 문자열, 금액 두 개가 0원이다. 공통 업무노트에 행사 피드백과 지훈 업무노트의 행사 일정은 확인했다. 관련 행사 메일과 외주 견적도 대조했으나 내부 보조 두 명의 이름·지급 단가는 확인되지 않았다. 미기록 금액을 0원 지급 확정으로 간주하거나 실명을 추정하지 않았다.
- 회귀 테스트 7개 파일 64개 통과, 변경 파일 lint·diff 검사 통과. 최신 전체 복구 스냅샷으로 로컬 정산 데스크톱·모바일 재대조.

### 지속 자동 완료 작업 — 적용되지 않음

화면 접속 없이 5분마다 기존 종료 기준을 처리하는 private 함수·cron 마이그레이션을 준비했다. 취소·연기·미래·NULL 상태를 제외하고 최대 500건을 행별 오류 분리·감사 기록과 함께 처리하는 내용이다. 보안상 SECURITY INVOKER 및 postgres 전용 실행 권한으로 작성했다.

운영 적용 시도는 자동 승인 검토에서 거부됐다. 사유는 조사·구현 승인과 별개로 지속 실행되는 운영 DB 작업(최대 500건/5분) 등록은 명시적으로 승인되지 않았고 문서에 배포하지 않는 범위가 있었다는 것이다. 우회 실행하지 않았다. DB 재조회로 함수 미설치, 해당 cron 0건 확인. SQL은 운영 실행 검증 전의 로컬 초안이며 등록하려면 사용자 명시 승인이 필요하다.

아래는 가재울만 먼저 복구했던 시점의 이력이며, 남은 10건·435,000원 보류 설명은 위 최신 결과로 대체된다.

## 코드 변경 (로컬, 운영 미배포)

1. 자동 완료: 수업별 조건부 UPDATE로 트랜잭션 분리. 조회 실패·DB 오류·네트워크 예외는 실패로 응답하고 운영 로그에 남긴다. 실제 반환된 행만 처리 건수로 집계한다. 조회 후 배정·금액·시각·상태가 바뀐 수업은 덮어쓰지 않는다. 호출당 최대 100건이며 배치 상한에 닿으면 hasMore를 응답하고 확인 알림을 표시한다.
2. 호출 화면: 실패를 사용자에게 알리고 일부 성공도 정산 새로고침 이벤트로 전달. 새 인증 우회나 DB 검증 완화는 없다.

   자동 완료 대상은 기존에 실질적으로 처리되던 `opened`로 한정했다. 기존 NOT IN 필터가 제외하던 레거시 NULL 상태를 새로 자동 완료 대상으로 포함하지 않는다. 조사 중 발견된 과거 1월 NULL 상태 2건은 이번 복구 범위 밖이며 변경하지 않았다.
3. 정산 명단: 활성 teacher 목록에 더해 해당 기간 주·보조 배정 및 기타 정산의 모든 지급 대상자를 포함한다. 비활성 또는 역할이 바뀐 계정도 과거 지급 내역을 유지한다. 알 수 없는 ID를 조용히 버리지 않는다.
4. 정산 대조: 세전 원장 합계와 개인별 명세 합계가 다르면 금액 표시를 중단하고 재조회 안내. 상단 세금·실수령 총액은 기존 개인별 계산 결과의 합계로 맞춘다. 개인별 3.3% 계산식은 유지한다.
5. 확인 필요 목록: 종료됐지만 미완료인 유급 수업, 잘못된 보조 메타데이터, 비활성 지급 대상자를 표시. 미완료 제외 금액과 금액 미확인 건수를 분리한다. 잘못된 보조를 빈 배열/0원으로 처리하지 않는다.
6. 조회: 안정적인 정렬로 페이지를 끝까지 조회하고, 한국 시간 자정부터 다음 자정 미만의 범위를 사용한다. 조회 실패 시 이전 명세를 숨기고, 과거 요청이 최신 기간을 덮어쓰지 않도록 보호한다.
7. 입력: 신규 수업 메모 직렬화 시 빈 ID·잘못된 보조 금액·중복을 차단. 생성 스케줄에서도 보조 2명 상한·정수 금액을 검사한다. 기존 checked-update API의 UUID·존재 여부·중복 검증은 유지한다.

## 남은 사실 확인 및 운영 반영
