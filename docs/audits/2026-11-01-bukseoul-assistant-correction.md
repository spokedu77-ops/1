# 북서울 10/21·28 보조 삭제 정정 — 최신 금액 기준

> 아래 3,660,000원은 대치 게이트 재개설 이전 스냅샷이다. 재개설 후 현재 합계 **3,900,000원**과 후속 개선은 [6단계 검사 결과](./2026-11-01-classops-six-stage-audit.md)를 따른다. 북서울 이승범 보조 지급 제외는 유지된다.

사용자는 두 수업에서 이승범 보조를 제거했다고 명시했다. 조회 시 DB에는 두 수업 모두 이승범/25,000원이 남아 있었고, 앞선 조사에서는 이 배정을 정상 지급 대상으로 간주했다. 특히 에이전트가 10/28 상태를 finished로 변경하면서 남아 있던 배정 25,000원도 집계되었다. 앞선 3,710,000원은 사용자의 삭제 의도를 반영하지 못한 금액이므로 철회하고 아래 결과로 대체한다.

## 운영 데이터 정정 완료

- 두 수업의 기존 main/fee/status/memo를 조건부 비교하고 보조 배열만 빈 배열로 변경했다. 상태·날짜·시간·주강사·주강사료는 유지했다.
- 10/21 `ed8d50e7-ee4c-4f02-8136-b5c0df547194`, 감사 ID `1db2ea66-9ea9-4d76-b283-58b4546a129c`.
- 10/28 `4417c145-3037-4279-9e5f-748b5671e1da`, 감사 ID `92cd8b91-dd59-420c-91b8-5b83543a86f8`.
- 실제 DB 재조회: 두 수업 이승범 배정 0, 보조 회차 로그 각각 0, 주강사 회차 로그 각각 1 유지.
- 수정 후 10월 후기 이승범 수업료 0원, 전체 수업료 3,630,000원 + 기존 기타 정산 30,000원 = **3,660,000원**. 지급·송금 실행은 하지 않았다.
- 이번 세션 복구·정정 감사 기록 19개 대조: 날짜·시간·주강사·주강사료 변경 0건. 이 결과만으로 운영 전체의 모든 과거 데이터가 정상이라고 단정하지 않는다.

## 저장 오류 조사 및 코드

- 운영 Postgres 로그의 보조 memo UPDATE 실패는 `SESSION_COUNT_EXTRA_TEACHERS_INVALID`, schedule conflict guard의 `session_count_teacher_ids` 호출이었다. 서버가 요청 수업 ID를 로그에 남기지 않아 해당 로그를 북서울 두 수업의 삭제 시도로 단정하지 않는다.
- DB 함수는 잘못된 기존 보조 메모를 엄격하게 읽다가 유효한 새 메모로 고치는 요청도 차단할 수 있다. 특히 이미 확인된 대치 운동회의 빈 ID는 이 결함에 해당한다.
- checked-update API에 수업 ID/실제 DB 오류 코드를 기록하고 메타데이터 오류(422)·회차 불일치(409)를 연결 장애와 구분했다. 화면은 입력을 유지하고 원인을 표시하며 예상된 저장 거절에 console.error를 호출하지 않는다.
- 보조 삭제 시 새 일정 충돌을 만들 수 없다는 조건(동일 시각·새 강사 추가 없음)에서 제거된 예약만 삭제하고, 잘못된 미완료 기존 메모는 유효한 새 메모의 전체 충돌 검증으로 교체할 수 있는 제한적 SQL 수정안을 작성했다.
- 최초 자동 승인 검토에서는 명시 승인 부족으로 거부됐으나, 이후 사용자가 “어 승인하고”라고 승인했다. 운영 마이그레이션 `20261031195642_classops_allow_safe_assistant_removal.sql` 적용 완료. 실제 운영 트랜잭션에서 기존 잘못된 메모 수정 성공·새 강사 시간 충돌 거절을 확인하고 테스트 변경은 전부 롤백했다.
- 대치 게이트 오류 수업은 사용자의 명시 삭제 요청에 따라 원본을 감사 기록에 보관한 뒤 해당 1건만 삭제했다. 자세한 최종 결과는 [저장 검증·대치 게이트 삭제 결과](./2026-11-01-class-save-persistence-result.md)를 참조한다.
- 점검 중 잠시 중지했던 기존 화면 자동 완료를 재개했다. 신규 상시 cron은 승인되지 않아 등록하지 않았으며 미적용 초안도 제거했다.

## 검증

- 최신 대상 회귀 테스트 6개 파일 60개 통과. 변경 파일 lint 및 TypeScript 결과는 최종 저장 검증 보고서에 기록한다.
- 운영 DB 읽기 전용 재조회로 배정·회차 로그·최종 합계 확인. UI 격리 검증은 별도 결과 파일에 기록한다.
- 커밋·푸시·배포 없음. 다른 작업의 변경 사항은 포함하지 않는다.
