## 재발 방지 변경 — DB 운영 적용 완료 / API 로컬 미배포

1. 교사 피드백 저장의 날짜 판정을 한국 시간으로 통일했다.
2. 관리자 피드백 저장·검수 API에도 미래 날짜 차단과 조회 후 날짜/수정시각 변경 감지를 추가했다.
3. 단건·일괄 일정 수정에서 완료 또는 피드백 기록이 있는 수업을 다른 오늘·미래 날짜로 옮기지 못하도록 했다. 과거 기록을 지우거나 새 수업으로 재사용하지 않는다.
4. INSERT, UPDATE, RPC, 직접 쓰기에서 같은 규칙을 원자적으로 적용하는 DB 트리거 마이그레이션을 작성했다. 미래 날짜에 피드백 또는 완료 상태를 저장할 수 없고, 기존 완료 기록을 오늘·미래로 이동할 수 없다. 기존 데이터 일괄 수정, 가격 변경, cron 등록은 없다.
5. 재실행 가능한 읽기 전용 전수조사 스크립트와 해당 1건에 한정된 보존·조건부 복구 스크립트를 추가했다.

사용자가 SQL 실행과 계정 연결을 명시 승인한 뒤, 기존 Vercel 인증을 갱신하고 Supabase CLI 브라우저 인증을 완료했다. 인증된 프로젝트 목록과 실제 수업 ID를 대조해 운영 프로젝트 `mwgvserdyflsqyhcqecp`를 확인했다. Supabase Management API를 통해 마이그레이션 `20261102070000`을 트랜잭션으로 운영 적용하고 마이그레이션 이력에 정확한 SQL을 등록했다.

DB 트리거가 현재 운영 쓰기를 차단하므로 API 미배포 상태에서도 기존 API·RPC·직접 쓰기에 적용된다. API 변경은 더 이른 요청 검증과 안내를 위한 로컬 변경이며 아직 배포하지 않았다.

### SQL 적용과 실제 차단 검증

- 단일 트랜잭션에서 대상 수업과 미적용 상태를 확인하고, 5초 잠금 제한 및 25초 문장 제한으로 해당 마이그레이션만 실행했다. 검증 실패 시 전체 롤백하도록 구성했다.
- authenticated 역할의 임시 수업에서 미래의 빈 수업·보조강사 메타데이터 저장, 오늘 피드백 작성, 같은 날짜 내 시간 수정이 허용됨을 확인했다.
- 미래 수업의 구조화 피드백·레거시 템플릿·사진·첨부·finished·verified 저장 및 피드백을 포함한 신규 미래 수업 INSERT가 차단됨을 확인했다.
- 과거 기록을 오늘로 이동하거나, 피드백을 비우면서 오늘로 이동하는 요청 모두 차단됨을 확인했다.
- service_role 역할로 실제 미래 수업에 피드백 UPDATE를 시도해 `SESSION_FUTURE_FEEDBACK_FORBIDDEN`을 확인했다. 실제 과거 완료 수업을 오늘로 이동하는 UPDATE도 `SESSION_RECORDED_SCHEDULE_MOVE_FORBIDDEN`으로 거부됐다. 예외 처리 하위 트랜잭션 안에서 확인했으며 실제 수업 수정은 남지 않았다.
- 적용 전후 전체 sessions 행의 ID 정렬 JSON 해시와 완료 집계 로그 건수가 같음을 확인하고 커밋했다.
- 별도 요청으로 마이그레이션 이력, 트리거 활성 상태 `O`, 두 함수의 SECURITY INVOKER 유지, 미래 220건 중 위반 0건, 오늘 중구 10남의 빈 피드백을 다시 확인했다.
