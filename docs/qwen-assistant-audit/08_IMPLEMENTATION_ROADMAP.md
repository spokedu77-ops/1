# 08. 구현 순서

점수는 감사 기준 7항목을 한 줄로 줄인 것이다. 코드는 아직 수정하지 않는다.

| 순서 | 업무 가치 | 재사용 | 난이도 | 데이터 위험 | 먼저 할 일 |
|---|---|---|---|---|---|
| P1 연결 | 높음 | 전부 기존 | 낮음 | 읽기만 | 임베딩 로드, MCP 읽기 3종 |
| P2 기억 | 높음 | RAG DB | 중간 | 재색인은 Drive 읽기 | 색인 갱신 절차와 출처 필드 고정 |
| P3 통제 | 높음 | tool_errors 패턴 | 중간 | 로그 추가만 | 성공 로그, 승인 플래그 점검 |
| P4 비서 확장 | 중간 | 세션·시트 도구 | 높음 | 쓰기 생김 | 월간 수업 읽기 집계부터. 정산 쓰기는 제외 |
| P5 피드백 학습 | 낮음(교정 큐와 다름) | 기존 잡 결과 | 높음 | 프롬프트 오염 | P1~P3 전에 시작하지 않음 |

## Phase 1 — 연결 정상화

수정 파일: 없음이 기본. 실패 원인이 코드일 때만 `server.py`의 오류 문자열.

확인: `get_current_datetime`, `search_rag_knowledge`(짧은 질의), `get_sessions_by_date`(오늘).

영향: 외부 쓰기 없음. DB 변경 없음.

롤백: LM Studio에서 임베딩 언로드. 설정 파일을 바꿨다면 예시 JSON 기준으로 되돌린다.

테스트: 세 호출의 반환 JSON에 `ok` 또는 문서화된 오류 코드가 있을 것. 모델이 0건을 “동기화 장애”로 말하지 않을 것(지침).

## Phase 2 — 장기기억

수정 후보: `rag_index.py` 재실행 진입점(이미 스크립트), 지침 한 절.

하지 말 것: 새 벡터 DB, memories에 메일 본문 저장.

영향: 로컬 `rag_index.db` 갱신. 운영 Supabase 없음.

롤백: DB 파일 복사본을 색인 전에 같은 폴더에 둔다.

테스트: 문서 1개의 제목이 검색 결과에 `file_id`와 함께 나오고, 색인 안 된 파일은 “확인 못 함”으로 남는지.

## Phase 3 — 실행 통제

수정 후보: `storage.py`의 `log_tool_failure` 옆에 성공 한 줄. 인자 원문·메일 본문·토큰은 넣지 않는다.

영향: 로그 파일만. 승인 없는 쓰기 기능 추가 금지.

롤백: 로그 함수 호출 제거.

테스트: 읽기 성공 1회가 로그에 남고, 실패는 기존 파일에도 남는지. `user_approved` 없는 Calendar 쓰기가 거절되는지는 스테이징 캘린더 없이 단위 테스트로만.

## Phase 4 — 업무 확대

우선 한 기능: “이번 달 수업”을 일별 조회를 31번 돌리지 않고 읽는 조회. 기존 `get_sessions_by_date`가 범위 인자를 받지 않으면 그 함수에 `date_to`를 더하는 수준.

정산 쓰기, Gmail 대량 발송, YouTube 업로드를 비서 기본 도구로 올리지 않는다. 업로드 스크립트는 `SPOKEDU-Assistant`에 이미 있고 보고서도 있다. Qwen 기본 루프와 합치지 않는다.

DB 마이그레이션: 불필요하면 하지 않는다.

## Phase 5 — 피드백으로 모델 개선

기존 n8n 교정 큐를 유지한다. 그 출력을 LoRA 데이터로 쓰지 않는다. 반복 오류는 로그의 reason 빈도부터 센다.

평가 셋이 생기기 전에는 학습 잡을 제안하지 않는다.

## 다음 승인 요청 (구현 착수 전)

1. Phase 1 읽기 호출 3개를 이 PC에서 실행해도 되는지.
2. 감사 문서 9개를 이 경로에 둔 것을 유지할지, 문구를 고칠지.
3. 코드 변경은 Phase 3의 성공 로그부터 할지, README 정정만 할지.

## 추가 (2026-11-08 검증 후 분석)

구현은 하지 않는다.

1. **지금 업무에 쓸 수 있는 도구:** 호출로 확인한 것은 `get_current_datetime`, `search_rag_knowledge`, `get_sessions_by_date` 세 개다. 날짜와 일별 수업 읽기는 응답이 정상이었다. RAG는 호출은 되나 이번 질의의 순위가 기대 문서를 1위에 두지 못했다. 나머지 22개는 여전히 미호출이다. 그 가운데 읽기로 다음 후보가 되는 것은 Drive·Sheets·Calendar 조회이고, Gmail 발송과 Calendar 쓰기·삭제는 승인 설계가 있으므로 후순위다.
2. **RAG:** 임베딩을 올리면 검색 자체는 약 11초에 3건을 돌려준다. 지식 활용 수준은 “제목이 비슷한 상위 후보를 사람이 고르는 단계”다. 가이드라인 문서가 부분 색인인 점과, 서로 다른 강의계획서 두 건의 점수가 동일한 점이 정확도의 한계다.
3. **개인 비서에 부족한 것:** 월간 수업 집계, 담당 강사 이름(이 조회는 등록자와 강사를 구분하고 강사명은 비운다), 검색 1위 신뢰, 성공 실행 로그, 대화에 기억을 자동으로 넣는 경로.
4. **n8n:** 이번 세 기능과 무관하게 꺼져 있다. 피드백 문장 교정을 다시 돌리기 전에는 복구할 필요가 없고, 비서 읽기 경로를 고치는 작업보다 앞당기지 않는다.
5. **관리자 화면:** 수업 조회 결과의 원천은 이미 관리자가 보는 세션 데이터다. MCP 상태를 붙이려면 기존 교사·수업 화면에 읽기 전용 상태 줄을 두는 편이 새 페이지보다 범위가 작다. 이번 단계에서 화면은 만들지 않는다.
