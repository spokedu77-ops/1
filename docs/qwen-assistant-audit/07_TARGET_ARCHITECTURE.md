# 07. 목표 구조 (구현하지 않음)

새 Supabase 프로젝트, 새 벡터 서버, 새 대시보드 앱을 만들지 않는다. 있는 프로세스를 한 줄로 잇는다.

```text
관리자 화면 (기존 teachers-classes + 얇은 비서 패널)
        │  읽기 / 승인 버튼
        ▼
Qwen  qwen3.5-9b  +  임베딩 0.6B 동시 로드   (LM Studio :1234)
        │
        ├─ MCP spokedu-assistant (기존 server.py)
        │     읽기: 세션, Drive, Sheets, Calendar, Gmail, RAG
        │     쓰기: 기억·할일·캘린더·메일 — 기존 승인 플래그 유지
        │     Supabase 원본 쓰기는 계속 금지
        │
        ├─ 장기기억 = 기존 SQLite 두 개
        │     memories: 사용자가 명시한 사실만
        │     rag_index: 업무 문서 (재색인 명령만 추가, 자동 삭제 없음)
        │     피드백 교정 결과는 여기 복사하지 않음
        │
        ├─ n8n 기존 Pull (active는 사람이 켤 때만)
        │     피드백 문장 교정 전용. 일반 비서 큐로 확장하지 않음
        │
        └─ 실행 기록
              tool_errors.log를 지우지 말고
              성공 한 줄(시각, 도구, 대상 id, ok)을 같은 logs 폴더에 추가
```

## 최소안 vs 통합안

최소안: 코드 변경 없이 LM Studio에서 `qwen3.5-9b`와 `text-embedding-qwen3-embedding-0.6b`를 같이 로드하고, 채팅에 기존 지침을 붙인 뒤 읽기 도구 3개만 확인한다. 실패하면 OAuth·Supabase 로그인만 고친다.

통합안: 최소안 이후 `server.py`에 성공 로그 한 함수를 넣고, README를 25도구로 고치고, 교사 화면 옆에 “마지막 MCP 오류 20줄”을 읽는 기존 관리자 라우트만 추가한다. 새 4분할 앱은 만들지 않는다.

화면을 나눈다면 기존 관리자에 네 덩어리를 섹션으로 둔다.

- A 대화·승인: LM Studio를 대체하지 않는다. 승인 버튼만 제품에 둔다(Gmail은 이미 로컬 스크립트).
- B 지식: RAG 문서 수, 마지막 색인 시각, memories 개수. 본문 전체 노출 금지.
- C 도구: 25개 이름과 마지막 오류.
- D 작업: `admin_feedback_correction_jobs` 최근 행(이미 API가 있음)과 MCP 성공 로그.

별도 `/admin/ai`를 새로 만드는 쪽은 내비게이션·권한·시각 계약을 건드린다. 통합이 유지보수 비용이 낮다. 이번 단계에서 화면 코드는 쓰지 않는다.

파인튜닝은 제안 조건: 같은 질문 50개에 대해 RAG+지침 후에도 형식 오류가 반복되고, 그 쌍이 파일로 남을 때. 그 전에는 LoRA를 열지 않는다.
