# 03. 기억·학습 감사

가중치를 바꾼 추가학습과, 프롬프트·SQLite·RAG·대화 로그를 분리한다.

## A. 기본 모델

- 실행: LM Studio, `127.0.0.1:1234`.
- 로드: `qwen3.5-9b` (`/api/v0/models`, state=loaded).
- 양자화·컨텍스트 길이: 이 API 필드에서 확인하지 못했다. `Q6_K`는 이번 조사의 사실이 아니다.
- 가중치 변경: 어댑터·학습 스크립트·체크포인트 없음. **변경 기록 없음.**

## B. 시스템 프롬프트

- 파일: `LM_STUDIO_ASSISTANT_INSTRUCTIONS.md`.
- 내용: 날짜 도구 우선, 0건을 장애로 단정하지 않기, 기억은 명시 요청 시만, Calendar·Gmail 승인, RAG 우선, 메일 본문을 기억·RAG에 넣지 않기.
- 로딩: 파일이 있다고 채팅에 들어가 있지 않다. LM Studio UI에 붙여 넣었는지는 **UNVERIFIED**.

## C. 대화 장기기억

- 저장: `spokedu_assistant.db`의 `memories` **1건**. 대화 전문 저장소가 아니다.
- 검색: `search_memory` 부분 일치. 새 채팅이 자동으로 기억을 넣지 않는다. 모델이 도구를 호출해야 한다.
- 삭제 API: README는 삭제 도구가 없다고 한다. 코드에도 memory delete 도구가 없다.
- LM Studio 자체 채팅 히스토리는 이 저장소 밖에 있을 수 있다. 이번 감사는 그 UI DB를 열지 않았다.

## D. 업무 지식

- RAG 색인: 문서 **347**, 청크 **1,147**. Drive의 google_doc·text_file만 (`INDEXABLE_TYPE_LABELS`). 상한 문서 20이 한 번 실행 기준인지 누적인지는 색인 코드의 `MAX_DOCS = 20`이 “한 배치”에 가깝다. 347은 여러 번 쌓인 결과로 보는 것이 맞다. 본문이 원문인지 요약인지는 청크를 덤프하지 않아 구분하지 않았다.
- 워크스페이스 인벤토리: `workspace_inventory.db`에 폴더 스캔 후 **21,683** upsert, classify 21,683 (`logs/inventory_run.json`). RAG 청크 수와 다르다. 목록과 검색 가능 본문은 별개다.
- 수업·정산·강사 지식 전용 코퍼스는 없다. 세션은 Supabase 조회 도구뿐이다.

## E. RAG

- 임베딩: Qwen3 embedding 0.6B, 1024차원, LM Studio `/v1/embeddings`.
- 벡터 DB: 로컬 SQLite. 별도 벡터 서버 없음.
- 갱신: 자동 감시 데몬을 찾지 못했다. 색인 스크립트를 다시 돌려야 반영된다.
- 출처: 지침이 `title`, `file_id`를 말하게 한다. 권한 필터는 Drive 색인 시점의 계정 범위다. 검색 시 사용자별 ACL을 다시 거는 구조는 이번 파일에서 확인하지 못했다.
- 지금: 임베딩 모델 **not-loaded**. 검색 함수가 임베딩 API를 부르면 실패한다. 그래서 “색인 1,147”과 “지금 검색 가능 1,147”은 같지 않다. 검색 가능 수는 **미검증(아마 0)**.

## F. 피드백 개선

- 제품 기능은 교사 피드백 문장 교정 큐다. 모델 성격·업무 규칙을 고치는 루프가 아니다.
- 오류 유형 분류기, 수정 전후를 다음 프롬프트에 자동 주입, 동일 오류 재발 검증 테이블은 비서 쪽에 없다.
- 과거 수치(피드백 1,088, 표본 29, 후보 829)는 이 저장소 문서 검색에서 찾지 못했다. 사실로 적지 않는다.

## G. 추가학습

- Fine-tune, LoRA, QLoRA, 학습 로그, 평가 전후: **없음.** 추가학습 완료로 기록하지 않는다.

## 필수 10문

1. Qwen이 SPOKEDU를 “아는” 부분은 베이스 모델의 일반 지식과, 도구가 돌려주는 RAG·Supabase·Drive 결과뿐이다.
2. 저장 위치는 위의 SQLite 두 개(기억 DB, RAG DB)와 인벤토리 DB, 지침 마크다운이다.
3. 새 대화에서 유지되는 것은 DB 행과 색인뿐이다. 자동 주입은 없다.
4. Drive 원본이 바뀌어도 색인을 다시 돌리기 전에는 RAG가 그대로다.
5. 잘못된 답을 고쳐도 가중치·규칙 저장소에 들어가지 않는다. `save_memory`를 사용자가 명시할 때만 한 줄이 남는다.
6. 반복 실수를 막는 구조는 시스템 지침 문장뿐이다. 적용 여부는 UI 붙여넣기에 달려 있고 검증되지 않았다.
7. 가중치 변경 증거 없음.
8. 축적량: 기억 1, 작업 1, RAG 문서 347·청크 1147, 인벤토리 21683, Gmail 승인 행 1, 발송 승인 0.
9. 미사용·중복: README의 6도구 설명, 확인되지 않는 워크플로 ID·5681, 로드되지 않은 Gemma·abliterated·nomic 임베딩, RAG와 별도인 인벤토리(검색 본문이 아님).
10. 장기기억으로 가려면 임베딩 상시 로드, 색인 갱신 절차, 대화가 아닌 “업무 사실”만 넣는 저장, 출처·시각, 그리고 도구 성공 로그가 먼저다. 파인튜닝은 그 다음에 평가 셋이 있을 때만.

## 추가 (2026-11-08 RAG 호출)

임베딩 모델을 추가 로드한 뒤 `search_rag_knowledge("센터 수업 가이드라인")`가 `ok=true`와 결과 3건을 반환했다. 색인 문서 `(25ver.)SPOKEDU 센터 수업 가이드라인`은 3위(유사도 0.604)이고 `partial_index=true`다. 1·2위는 `강의계획서양식(간략).docx`, `강의계획서_25회차.docx`로 유사도가 둘 다 0.610이다. 같은 점수는 청크가 거의 같거나 임베딩이 질문을 문서 제목과 약하게만 구분한다는 뜻이다. 검색은 동작하고, 기대 문서를 1위로 올리지는 못했다. 발췌 본문은 감사 문서에 옮기지 않았다. 가중치 변경은 없다.
