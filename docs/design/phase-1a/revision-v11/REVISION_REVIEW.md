# SPOKEDU Phase 1-A · V1.1 검토

## 1. 범위와 상태

- 작업 모드: `DESIGN_ONLY`
- 변경 범위: 독립 Hero A/B 시안과 서비스 선택 카드 시안
- 보존: Phase 1-A 디자인 시스템, 모바일 메뉴, 운영 페이지, 기능과 경로
- Production 코드 변경: 없음
- 최종 디자인: 미확정

## 2. 기존 Phase 1-A 대비 변경

### Home Hero

- 영문 슬로건의 `opacity: 0.12` 표현을 제거하고 실제 Brand Blue로 읽히도록 조정했다.
- A안은 한글 H1을 1차 메시지, 영문을 2차 브랜드 서명으로 구성했다.
- B안은 기존 Home의 108px 계열 에디토리얼 감도를 참고해 영문을 최대 102px 중심 요소로 구성했다.
- 실제 위례초 원경 사진 대신 움직임과 화면 반응이 더 뚜렷한 실제 동작 키움센터 SPOMOVE 사진을 A/B에 동일하게 사용했다.
- 모바일 A안은 `한글 제목 → 설명 → 사진 → CTA`의 핵심 순서를 지키고, 영문은 제목 인접 보조 타이포그래피로 배치했다.
- 모바일 B안은 큰 영문과 한글 메시지를 함께 보여주되 사진과 CTA가 390×844 첫 화면 안에 이어지도록 압축했다.

### Service Card

- 서비스 수와 문구, 고객 유형, 링크 목적지는 Phase 1-A와 동일하게 유지했다.
- 불필요한 최소 높이를 줄이고 번호, 4px 상단 구분선, 분리된 하단 링크 영역으로 정보 강약을 만들었다.
- 제목은 24px, 설명은 15px/1.65로 조정하고 링크 전체 행을 클릭 가능한 영역처럼 보이게 했다.
- 모바일은 카드 최소 높이를 제거하고 19px 제목, 14px 설명, 48px 링크 행으로 압축했다.
- 이미지·아이콘·그라데이션은 추가하지 않았다.

## 3. A안 — 한글 메시지 중심

### 장점

- 고객이 브랜드를 처음 보더라도 한글 핵심 약속을 가장 먼저 이해한다.
- 영문은 40px Brand Blue로 분명히 보이지만 한글보다 앞서지 않는다.
- 데스크톱 split hero의 정보 순서가 명확하고 CTA까지 자연스럽게 내려간다.
- 모바일에서 설명 뒤에 실제 사진이 바로 이어져 Phase 1-A보다 현장 사진을 일찍 만난다.

### 단점

- 기존 SPOKEDU의 대형 영문 Display가 주는 독특한 첫인상은 B안보다 약하다.
- 전형적인 신뢰형 교육 브랜드 Hero에 더 가까워 보일 수 있다.

## 4. B안 — 에디토리얼 특징 강화

### 장점

- `MOVEMENT BECOMES LEARNING.`이 최대 102px로 화면의 시각적 리듬을 주도해 기존 Home의 개성이 강하다.
- 큰 영문, 실제 움직임 사진, 한글 메시지가 함께 있어 스포츠 에디토리얼 인상이 분명하다.
- 모바일에서도 영문이 장식이 아니라 브랜드 자산으로 읽힌다.

### 단점

- 처음 보는 고객은 한글 메시지보다 영문을 먼저 볼 가능성이 있다.
- 작은 모바일 화면에서 영문 세 줄이 차지하는 공간이 커 A안보다 설명과 CTA가 조밀하다.
- 장기적으로 영문 Display와 한글 H1의 위계 규칙을 더 엄격히 관리해야 한다.

## 5. 고객·브랜드·모바일 비교

| 평가 기준 | 기존 Phase 1-A | A안 | B안 |
|---|---|---|---|
| 브랜드 인지도 | 영문이 12% 투명도로 흐려 워드마크 외 브랜드 문장이 약함 | Blue 영문을 선명하게 복구하되 한글 아래에 두어 균형적 | 대형 영문이 첫 장면을 주도해 기존 에디토리얼 정체성이 가장 강함 |
| 고객의 즉각적 이해 | 한글 H1은 명확하지만 긴 영문 블록과 설명 사이 관계가 느슨함 | 한글 H1 → 설명 → 행동의 의미 순서가 가장 직접적 | 한글도 충분히 크지만 영문이 먼저 시선을 받아 이해 속도는 A안보다 다소 느릴 수 있음 |
| 체육교육 현장감 | 위례초 원경 사진에서 공간 비중이 크고 인물이 작음 | SPOMOVE 참여 장면을 크게 보여 활동과 현장성이 강화됨 | 같은 실제 사진에 큰 스포츠형 타이포를 결합해 역동성이 가장 강함 |
| 타이포그래피 완성도 | 큰 여백은 좋지만 희미한 영문 때문에 의도보다 미완성처럼 보임 | 한글 62px과 영문 40px의 위계가 안정적 | 최대 102px 영문과 42px 한글의 대비가 강하며 개성이 뚜렷함 |
| 모바일 첫 화면 | 텍스트·CTA 뒤 약 640px 아래에서 사진이 시작 | Hero 진입 후 약 264px, 전체 화면 상단에서 약 378px에 사진이 시작되어 의미 흐름이 자연스러움 | 전체 화면 상단에서 약 424px에 사진이 보여 첫 화면에 남지만 정보 밀도는 A안보다 높음 |
| CTA 명확성 | Primary/Secondary 구분은 명확 | 사진 다음 CTA로 실제 장면을 본 뒤 행동 선택 | 동일 문구와 위계지만 큰 영문 때문에 CTA의 상대적 시각 비중은 A안보다 낮음 |

이 비교는 렌더 결과에 대한 디자인 판단이다. 실제 고객 테스트, 전환율 또는 객관적 사용성 점수를 의미하지 않는다.

## 6. 서비스 카드 개선 평가

- 기존 문제: 세 카드가 동일한 흰색 상자와 작은 텍스트로 보여 서비스 간 구분과 링크 클릭 가능성이 약했다.
- 개선: 동일한 카드 문법 안에서 서비스별 색 선과 번호를 사용하고, 고객 유형 → 제목 → 설명 → 독립 링크 행의 순서를 강화했다.
- 통일성: Blue/Navy, Pretendard, 16px 카드 반경, 공통 Border, Text Link 문법을 유지했다.
- 기관 Orange는 굵은 비텍스트 선과 큰 장식 번호에만 사용한다. 작은 본문에는 사용하지 않는다.
- 모바일은 1열과 20px gutter를 유지하면서 카드의 불필요한 최소 높이를 제거했다.

## 7. 기능 검증과 시각 검증 구분

- 기능 검증: A/B 전환, 카드 기존/개선 전환, CTA href 동일성, `aria-pressed` 갱신을 확인한다.
- 시각 검증: 1440×900 및 390×844에서 사진 노출, 타이포 위계, 겹침, 잘림, overflow를 별도로 검토한다.
- Playwright 성공만으로 최종 디자인 PASS를 선언하지 않는다. A/B와 최종 사진은 사용자 결정이 필요하다.

### Playwright 확인 결과

| 시안 | Viewport | 영문 크기 | 사진 시작 | 결과 |
|---|---:|---:|---:|---|
| Hero A | 1440×900 | 40px | 290px | 이미지 정상, overflow·clipping·브라우저 오류 없음 |
| Hero A | 390×844 | 20px | 378px | 사진과 두 CTA가 첫 화면 안에 표시, 겹침 없음 |
| Hero B | 1440×900 | 100.8px | 263px | 대형 영문과 사진·CTA가 첫 화면 안에 표시 |
| Hero B | 390×844 | 45px | 424px | 사진과 두 CTA가 첫 화면 안에 표시, 겹침 없음 |
| Service Card | 1440×900 | 해당 없음 | 해당 없음 | 3열 전체와 링크 행 표시, overflow 없음 |
| Service Card | 390×844 | 해당 없음 | 해당 없음 | 1열 카드 3개와 마지막 링크가 782px까지 표시 |

- 모든 시안의 문서 크기는 지정 viewport와 일치했고 가로 overflow는 0건이다.
- Hero 이미지와 로고는 모든 캡처에서 `naturalWidth > 0`으로 디코딩됐다.
- A/B의 Eyebrow, 한글 문구, 영문 문구, 설명, CTA 문구·href, 이미지 경로가 동일함을 정적으로 확인했다.
- A/B 전환과 카드 기존/개선 전환 후 활성 패널 및 `aria-pressed="true"` 갱신을 확인했다.
- CSS 선언은 Pretendard 우선 stack이지만 로컬 Pretendard 탐색은 실패했다. Windows 캡처는 뒤쪽 OS 한글 폰트 fallback으로 렌더링됐다.

## 8. 미확인 사항

- 실제 현장 사진은 내부 출처 계보가 있으나 공개 사용 상태가 `APPROVED`로 기록되지 않았다.
- 저장소에 Pretendard 폰트 파일이 없으므로 캡처 환경에서 실제 glyph는 OS fallback일 수 있다.
- 실제 고객 이해도 및 전환 성과는 테스트하지 않았다.

## 9. 최종 결정 필요

1. A안 또는 B안의 메시지 위계
2. 실제 Hero 사진 1~3순위 중 최종 후보와 공개 사용 승인
3. 서비스 카드의 번호·상단 색 선·분리 링크 행 적용 여부

Phase 1-B 구현은 별도 명시적 승인 전까지 시작하지 않는다.
