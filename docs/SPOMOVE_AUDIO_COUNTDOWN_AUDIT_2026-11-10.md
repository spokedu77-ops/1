# SPOMOVE BGM·시작 화면 점검 — 2026-11-10

이번 변경과 로컬 점검의 스냅샷이다. 제품 계약이나 실행 규칙의 SSOT를 대체하지 않는다.

## 수정

- 일반 HTMLAudio, MASTER, Flow, Unity DIVE의 BGM 실효 gain을 `app/lib/spomove/audioSettings.ts`의 0.65로 통일했다. 기존 값은 경로에 따라 0.275 / 0.35 / 0.54였다. SFX 음량은 유지했다.
- Unity DIVE는 시작 버튼의 사용자 제스처로 활성화한 Web Audio를 사용한다. 카운트다운 이후 음원 주소가 도착해도 시작 요청을 기억하여 재생한다.
- Flow는 늦게 준비된 음원을 stage-intro / speed-intro에서도 재생한다. 종료·해제 이후 로딩 완료가 재생을 되살리거나 일시정지를 해제하지 않도록 보호했다.
- Flow의 장면 준비와 음원 로딩을 병렬화하고 음원 요청에 12초 제한을 적용했다. 실패하면 활동을 재시작하지 않는 BGM 복구 버튼을 제공한다.
- 이동 숫자 읽기에 최초 3→2→1을 추가했다. 라운드별 READY 등 고유 진행 단계는 유지한다.
- MASTER 호환 라우터에서 moving-number-reader / visual-search의 실행 연결 누락을 수정했다.

## 느리거나 들리지 않았던 이유

Flow Web Audio는 MP3 전체 수신과 디코딩 후 재생하므로 스트리밍 HTMLAudio보다 준비 시간이 길다. 실제 음원 측정에서 전체 수신·디코딩은 약 1.46–3.76초였다. 일부 원본 음원 자체에도 조용한 도입부가 있다. 재생 속도는 1이며 의도적으로 느리게 재생하지 않는다.

Unity의 늦은 음원 경로 도착, 사용자 제스처 이후 생성된 오디오의 브라우저 차단, Flow의 도입 단계 재생 누락이 별도의 무음 가능 경로였다. 이번 수정은 이러한 코드 경로를 처리한다. 음원 원본 도입부는 편집하지 않았다.

## 남아 있는 차이와 확인 한계

- 카운트다운 시각 표현은 공통 주황색 오버레이, Flow 흰색+GO, Unity 흰색+GO, 선생님 직접 구성 화면의 네 계열이다. 숫자 순서 점검과 별개로 디자인은 아직 통일되어 있지 않다.
- MASTER의 비공개 glass-bridge-memory 호환 분기는 전용 유리 다리 실행기 대신 공간기억 분기를 사용한다. 공개 카탈로그에는 없으며 이번 오디오 수정에서 실행 의미를 변경하지 않았다.
- Unity 준비 메시지는 테스트에서 모사했다. Unity 내부 게임 렌더링, 실제 iPad/Safari의 자동재생 정책, 스피커에서 체감되는 음량은 이번 로컬 Chrome 검증 범위 밖이다.
- 운영 배포는 하지 않았다. 기존 결과 화면 및 사용자 관리 미커밋 변경은 보존했다.
